API

Three endpoints

The animation above maps directly to these calls.

  1. Ingest

    Send security events to POST /logs/ingest. They are stored in SQLite and run through the detection rules.

  2. Seal & anchor

    POST /logs/seal-batch hashes pending logs into a Merkle tree and commits the root to the smart contract.

  3. Verify

    GET /logs/batch/{id}/integrity recomputes the root from the stored logs and compares it with the on-chain value.

Detection engine

Detection rules

These rules run on every sealed batch. You can re-run them from the console.

RuleSeverityCondition
BRUTE_FORCEHIGH3+ failed login attempts from a single actor within 5 minutes.
BRUTE_FORCE_SUCCESSCRITICALSuccessful login following a brute-force burst within 1 hour.
PRIVILEGE_ESCALATIONCRITICALHIGHIAM permission changes. Raised to CRITICAL when Administrator access is granted.

LOG_TAMPERINGCRITICALStored logs do not match the root hash on the chain.

Integrity

Integrity verdicts

If the blockchain node can't be reached, verification fails closed. A tampered batch is never reported as intact.

INTACT
The logs match the root hash stored on the chain.
TAMPERED
The stored logs don't match the anchored root. This raises a CRITICAL alert.
UNVERIFIABLE
The blockchain is unreachable, or the batch is missing from the contract.
UNANCHORED
The batch is sealed locally but has not been committed to the chain yet.
